## Настройка Разработки

### Требования

- Node.js 14+
- MongoDB 4.4+
- npm или yarn
- Git

### Установка

```bash
# Форкните и склонируйте репозиторий
git clone https://github.com/ВАШ_НИК/PremiumEstateCRM.git
cd PremiumEstateCRM

# Установите все зависимости (сервер + клиент)
npm run install-all

# Настройте переменные окружения
# Сервер: Скопируйте server/.env.example в server/.env
# Клиент: Скопируйте client/.env.example в client/.env

# Запустите серверы разработки
npm run dev
```

### Запуск Тестов

```bash
# Запустить тесты сервера
cd server
npm test

# Запустить тесты клиента
cd client
npm test

# Запустить линтинг
npm run lint
```

## Руководство по Написанию Кода

### Общие Руководства

- Пишите чистый, читаемый код
- Следуйте существующему стилю кода
- Комментируйте сложную логику
- Делайте функции небольшими и сфокусированными
- Используйте значимые имена переменных

### Руководства JavaScript/React

- Используйте функциональные компоненты с хуками
- Используйте стрелочные функции для определения компонентов
- Деструктурируйте props, когда это возможно
- Используйте PropTypes или TypeScript для проверки типов
- Следуйте лучшим практикам React

**Пример:**
```jsx
// ✅ Хорошо
const PropertyCard = ({ property, onFavorite }) => {
  const { title, price, images } = property;
  
  return (
    <div className="property-card">
      <img src={images[0]} alt={title} />
      <h3>{title}</h3>
      <p>${price.toLocaleString()}</p>
      <button onClick={() => onFavorite(property.id)}>
        Избранное
      </button>
    </div>
  );
};

// ❌ Избегайте
function PropertyCard(props) {
  return (
    <div>
      <img src={props.property.images[0]} />
      <h3>{props.property.title}</h3>
    </div>
  );
}
```

### Руководства для Бэкенда (Node.js/Express)

- Используйте async/await для асинхронных операций
- Реализуйте правильную обработку ошибок
- Проверяйте все входные данные
- Используйте переменные окружения для конфигурации
- Следуйте соглашениям REST API

**Пример:**
```javascript
// ✅ Хорошо
const getProperty = async (req, res) => {
  try {
    const { id } = req.params;
    const property = await Property.findById(id);
    
    if (!property) {
      return res.status(404).json({ error: 'Объект не найден' });
    }
    
    res.json(property);
  } catch (error) {
    console.error('Ошибка получения объекта:', error);
    res.status(500).json({ error: 'Ошибка сервера' });
  }
};

// ❌ Избегайте
const getProperty = (req, res) => {
  Property.findById(req.params.id, (err, property) => {
    res.send(property);
  });
};
```

### Сообщения Коммитов

Мы следуем спецификации [Conventional Commits](https://www.conventionalcommits.org/):

```
тип(область): тема

тело (опционально)

подвал (опционально)
```

**Типы:**
- `feat`: Новая функция
- `fix`: Исправление ошибки
- `docs`: Изменения документации
- `style`: Изменения стиля кода (форматирование)
- `refactor`: Рефакторинг кода
- `test`: Добавление тестов
- `chore`: Изменения сборки/конфигурации

**Примеры:**
```bash
feat(offers): добавить расширенную систему фильтрации

fix(auth): исправить проблему истечения срока действия JWT токена

docs(readme): обновить инструкции по установке

refactor(property-card): оптимизировать производительность рендеринга

test(leads): добавить модульные тесты для компонента Kanban
```

## Процесс Pull Request

### Перед Отправкой

1. **Протестируйте ваши изменения**
   - Запустите приложение локально
   - Протестируйте все затронутые функции
   - Проверьте наличие ошибок в консоли

2. **Обновите документацию**
   - Обновите README.md при необходимости
   - Добавьте комментарии для сложного кода
   - Обновите CHANGELOG.md

3. **Запустите линтинг и тесты**
   ```bash
   npm run lint
   npm test
   ```

4. **Проверьте конфликты**
   - Сделайте ребейз на последнюю ветку main
   - Разрешите любые конфликты слияния

### Шаблон PR

При создании PR, пожалуйста, включите:

```markdown
## Описание
Краткое описание изменений

## Тип Изменений
- [ ] Исправление ошибки (не ломающее изменение, которое исправляет проблему)
- [ ] Новая функция (не ломающее изменение, которое добавляет функциональность)
- [ ] Ломающее изменение (исправление или функция, которая приведет к изменению существующей функциональности)
- [ ] Обновление документации

## Контрольный Список
- [ ] Мой код следует руководствам по стилю
- [ ] Я провел самопроверку
- [ ] Я прокомментировал мой код, особенно в трудно понятных местах
- [ ] Я внес соответствующие изменения в документацию
- [ ] Мои изменения не создают новых предупреждений
- [ ] Я добавил тесты, которые доказывают, что мое исправление эффективно или что моя функция работает
- [ ] Новые и существующие тесты проходят локально

## Скриншоты (если применимо)
Добавьте скриншоты, чтобы помочь объяснить ваши изменения.

## Связанные Задачи
Закрывает #(номер задачи)
```

### Процесс Рецензирования

1. **Автоматические Проверки** - Запускаются CI/CD пайплайны
2. **Проверка Кода** - Мейнтейнеры проверяют ваш код
3. **Обратная Связь** - Ответьте на любые комментарии или предложения
4. **Одобрение** - PR одобряется и сливается

## Руководство по Сообщению о Проблемах

### Метки

Мы используем следующие метки для категоризации задач:

| Метка | Описание |
|-------|----------|
| `bug` | Что-то не работает |
| `enhancement` | Новая функция или запрос |
| `documentation` | Улучшения документации |
| `good first issue` | Хорошо для новичков |
| `help wanted` | Требуется дополнительное внимание |
| `question` | Требуется дополнительная информация |
| `wontfix` | Не будет исправлено |
| `duplicate` | Уже сообщалось |
| `invalid` | Не действительная проблема |
| `priority: high` | Высокий приоритет |
| `priority: medium` | Средний приоритет |
| `priority: low` | Низкий приоритет |

### Жизненный Цикл Задачи

1. **Open** - Задача создана
2. **Triaged** - Мейнтейнер проверяет и добавляет метки
3. **In Progress** - Кто-то работает над этим
4. **Review** - Готово к рецензированию
5. **Closed** - Задача решена
